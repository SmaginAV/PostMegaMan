# Примеры импорта PostMegaMan

В этих примерах используются демонстрационные токены и API-ключи. Для импорта не требуется отдельный файл окружения Postman. Сеть понадобится только при отправке запроса в публичный сервис.

## 1. Сложная строка cURL

Файл: [curl-complex.txt](curl-complex.txt).

1. Открой запрос или создай новый.
2. Выбери **Импорт → Импортировать из cURL**.
3. Скопируй всю строку из файла и вставь в окно импорта. Выполнять команду в терминале не нужно.
4. Подтверди импорт и проверь поля.

Ожидаемый результат:

| Поле | Значение |
|---|---|
| Метод | `PATCH` |
| Адрес | `https://postman-echo.com/patch` с параметрами из команды |
| Таймаут | 45 секунд |
| Авторизация | Bearer, демонстрационный токен из команды |
| Query-параметры | В том числе два значения `tag`: `first` и `second` |
| Заголовки | Accept, Content-Type, Cache-Control и демонстрационные дополнительные заголовки |
| Тело | Вложенный объект `order` с читаемыми переносами строк |

Кавычки, кириллица, вложенные объекты, массивы и строковые значения должны сохраниться. Нажми **Перенести в конструктор**, чтобы посмотреть структуру тела.

## 2. Один запрос Postman

Файл: [postman-single-request.postman_collection.json](postman-single-request.postman_collection.json).

1. Выбери **Импорт → Импортировать из POSTman**.
2. Укажи файл примера.
3. Появится новый запрос **Одиночный POST JSON**. В WorkSpace до сохранения это черновик с `(*)`.
4. Проверь метод `POST`, адрес `https://postman-echo.com/post?source=single&tag=one&tag=two` и Bearer с демонстрационным токеном.
5. На странице **Параметры** должны остаться обе строки `tag`; отключённый `debug` не добавляется в итоговый URL.
6. В теле будут вложенные объекты и массивы. `Content-Type` — `application/json`; отключённый заголовок `X-Disabled` не отправляется.

Файл имеет формат коллекции Postman v2.1 с одним элементом без папок и используется как переносимый пример одного запроса.

## 3. Дерево запросов Postman

Файл: [postman-request-tree.postman_collection.json](postman-request-tree.postman_collection.json).

1. Укажи каталог **WorkSpace**. Для первой проверки удобно использовать пустой отдельный каталог.
2. Импортируй файл через **Импорт → Импортировать из POSTman**.
3. В WorkSpace появится новый каталог **PostMegaMan Import Demo** с таким деревом:

```text
PostMegaMan Import Demo/
├── Чтение/
│   ├── 01 GET - Bearer из коллекции.json
│   └── 02 HEAD - без авторизации.json
├── Изменение/
│   ├── JSON/
│   │   ├── 03 POST - вложенный JSON.json
│   │   └── 04 PATCH - API key в заголовке.json
│   └── 05 POST - urlencoded.json
├── Авторизация/
│   ├── 06 GET - Basic из папки.json
│   └── 07 GET - API key в query.json
└── Пустой каталог/
```

Получатся семь запросов. Прежние файлы WorkSpace сохраняются; повторный импорт создаёт отдельный каталог с числовым суффиксом.

Выбирай запросы в дереве и проверяй метод, параметры, заголовки, тело и авторизацию. Значения переменных берутся из файла коллекции; неразрешённые переменные приводят к отмене импорта.

## Отправка и ограничения

Нажатие **Отправить** обращается к Postman Echo. Доступность, задержка и ответы этого внешнего сервиса могут меняться. Импорт сам по себе запрос не отправляет.

PostMegaMan импортирует поддерживаемые настройки. Загрузка файлов, multipart, прокси и неподдерживаемые транспортные параметры не воспроизводятся автоматически; при влияющей на запрос неподдерживаемой настройке импорт отменяется с объяснением.
