# Двоичные ответы: локальный стенд

Требуется Python 3. Внешняя сеть и сторонние пакеты не нужны. Стенд слушает только `127.0.0.1:18763`, не записывает файлы в WorkSpace и не содержит секретов.

## Запуск

1. Открой PowerShell в этой папке.
2. Выполни `python .\server.py --fixtures .\fixtures` (или `py -3 .\server.py --fixtures .\fixtures`).
3. Оставь терминал открытым. В `fixtures` появятся PDF, PNG, ZIP и файл `SHA256.json` с размерами и эталонными хешами всех ответов.
4. Открой новую EPF. Для каждого примера ниже выбери `GET`, вставь URL и нажми **Отправить**. Повтори с контекстами **На клиенте** и **На сервере**.

На файловой базе оба контекста имеют доступ к этому адресу. На настоящем серверном кластере `127.0.0.1` относится к серверу: для такого теста нужен отдельный стенд, доступный с обеих машин.

## Примеры

| URL после `http://127.0.0.1:18763/` | Ожидается |
|---|---|
| `pdf` | Пустое тело, один диалог, имя `report.pdf`, повторная кнопка |
| `png` | PNG, имя `response.png`, MIME с другим регистром и параметром |
| `zip` | ZIP с текстовым файлом, имя `archive.zip` |
| `png-no-type`, `pdf-no-type` | Файл распознаётся без Content-Type |
| `pdf-text`, `png-text` | Файл распознаётся вопреки text/plain |
| `pdf-error` | PDF скачивается, код остаётся 500 |
| `octet`, `unknown`, `short` | Двоичные данные, включая короткий ответ и нулевой байт |
| `utf8-name` | Имя `Отчет тест.pdf` из filename* |
| `bad-name`, `path-name` | `ordinary.pdf`, `bad.pdf`: запасное имя и удаление пути |
| `json.pdf` | Читаемый JSON; расширение URL не создаёт скачивание |
| `xml`, `svg`, `cp1251`, `utf16`, `utf8-bom`, `attachment-text` | Текст, без диалога и кнопки; кириллица/кодировки сохранены |
| `empty`, `204`, `304` | Нет файла даже с MIME PDF |
| `large` | PDF с добавленными 16 МиБ данных; распознаётся по префиксу до 8192 байт |

Для метода `HEAD` по адресу `/pdf` скачивания также быть не должно. `/jpeg` и `/gif` — только короткие тесты сигнатур, не полноценные изображения для просмотра. `/jwt` возвращает демонстрационный JSON-токен `access_token`.

Примеры cURL для вставки через **Импорт → Импортировать из cURL**:

```text
curl --request GET --url http://127.0.0.1:18763/pdf --header "Accept: application/pdf"
curl --request GET --url http://127.0.0.1:18763/png --header "Accept: image/png"
curl --request GET --url http://127.0.0.1:18763/json.pdf
```

## Ручная проверка сохранения

1. Открой `/pdf`, отмени автоматический диалог. Тело пустое, **Скачать файл** доступна. Диалог сам не повторяется.
2. Нажми кнопку, сохрани PDF. Сохрани повторно под другим именем. Во время диалога кнопка остаётся видимой, действия с запросом недоступны.
3. В другом терминале выполни `Invoke-RestMethod http://127.0.0.1:18763/counters`. Значение `pdf` не должно увеличиваться от повторного скачивания.
4. Сравни файлы: `Get-FileHash -Algorithm SHA256 -LiteralPath 'C:\путь\report.pdf'`. Хеш должен совпасть с полем `pdf.sha256` файла `fixtures/SHA256.json`.
5. Выбери существующий файл и откажись от замены: он не должен измениться. Проверь ошибку записи в недоступный каталог и повтор в доступный. Полученный ответ и код HTTP должны сохраниться, блокировка — сняться.
6. Скрой/покажи боковую панель и обнови дерево: файл доступен. Отправь JSON, очисти форму, загрузи другой запрос или сохранённый JSON: кнопка должна скрыться. Файл ответа в JSON не переносится.
7. Измени запрос и переключись на другой с ответом **Да** на вопрос о сохранении: правая часть должна снова стать доступной. Проверь Tab и фокус редактора.
8. Для JWT укажи `/pdf`: токен не получен, файл можно скачать. Для `/jwt` и пути `access_token` штатно получается текстовый токен.

Остановка стенда — **Ctrl+C** в его терминале. Сгенерированные эталоны и скачанные файлы можно удалить после сравнения. Исторические выпуски проекта этим стендом не меняются.
